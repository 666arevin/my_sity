# Тестовый Markdown для проверки парных тегов

### 1. Таблица (разбивается при \n\n)

| Тег | Описание | Статус |
| :--- | :--- | :--- |
| ```` ``` ```` | Блок кода | Не ломается |
| `~~` | Зачеркивание | Ломается при \n\n |

### 2. Теги, которые НЕ ломаются при двойном переносе (\n\n)
Ниже открывается многострочный блок кода. Внутри него есть пустые строки (`\n\n`), но парный тег закроется корректно только в самом конце:

```javascript
function test() {
    console.log("Первый абзац кода");

    // Между этими строками два переноса \n\n
    console.log("Второй абзац кода");
}
```

### 3. Теги, которые ЛОМАЮТСЯ при двойном переносе (\n\n)
По спецификации Markdown, стандартное инлайн-выделение (зачеркивание, жирный, курсив) **не может содержать пустые строки**. Парный тег автоматически считается сломанным/незакрытым, если встретился новый абзац.

~~Это начало зачеркнутого текста, который мы забыли закрыть на этой строке.

А это уже новый абзац текста после двух переносов строк. Из-за \n\n тег выше остался сиротой. Вот парный тег в конце другого абзаца, который должен закрывать что-то еще~~

### 4. Краш-тест для регулярки (кавычки разной длины)
Здесь специально смешаны кавычки, чтобы проверить, что ваша регулярка ищет строго тройные:
* Вот валидный тег: ```
* Вот inline-код из одной кавычки: `code`
* Вот блок из четырех кавычек: ````строка```` (регулярка на 3 кавычки должна его пропустить)
* Вот закрывающий валидный тег: ```
